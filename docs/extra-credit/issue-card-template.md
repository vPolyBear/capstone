# issue-card-template

    - This template forces a requirement identifier, an estimate, and a stopping condition on every card created. This makes it harder to create a bad card, which is worth more than remembering to.

# Issue Card Template (Paste this into the Card)

    Task Description: <what will be done in this task>

    Estimate: ___ hours ___ minutes <guess on how long the task will take to be completed>
    Hat: <hat options are below>
    Stopping Condition: <condition that describes what will determine when this task is done>

# Card Example

    Task Description: Add in the ai-usage-temple.md into my repository and then fill in the header and do a deliberate Amber-zone use.

    Estimate: 45 minutes
    Hat: Product Manager
    Stopping Condition: The log entry has a policy header and two entires


# Hat Options (In order by week)

    - Project Manager (Week 1)
    - Product Owner (Week 2)
    - Business Analyst (Weeks 3-4)
    - Architect (Weeks 5-6)
    - Project Manager (Week 7)
    - Architect, defending the design (Week 8)
    - Developer (Weeks 9-10)
    - Tester (Week 11)
    - Developer (Week 12)
    - Technical Writer (Week 13)
    - Developer, wearing the release-engineer hat (Week 14)
    - Product Owner (Week 15)
    - Project Manager (Week 16)
